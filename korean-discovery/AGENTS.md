# AGENTS.md

# KOREAN DISCOVERY｜韓文探索誌

## 1. 專案介紹（Project Overview）

本專案是一個以韓文知識及韓國文化為主題的介紹型網站。

網站的主要目標是讓沒有韓文基礎的使用者，也能透過簡單、有趣且容易理解的內容認識韓文。

網站不是傳統的線上教學平台，而是以主題式閱讀為核心，結合語言知識、文化介紹、生活用語及有趣的語言現象。

### 核心目標
- 讓韓文知識更容易理解。
- 透過有趣的主題吸引讀者。
- 結合韓文與韓國文化。
- 建立可以持續新增文章的網站架構。

## 2. 網站設計風格（Design System）

整體採用韓系雜誌風格。

### 色彩規範
- 背景色：米白色（#F8F6F0）
- 主要文字：深墨色（#242424）
- 輔助色：韓式紅色（#C94C4C）
- 次要背景：淺灰色（#EFEDE7）

### 設計原則
- 保持簡潔、乾淨的版面。
- 使用適當留白，避免資訊過度擁擠。
- 使用清楚的標題與內文層級。
- 圖片應與文章主題相關。
- 所有頁面必須維持一致的視覺風格。
- 網站必須支援桌面與手機瀏覽。

## 3. 網站頁面結構（Page Structure）

網站主要包含以下頁面：

### 首頁（index.html）
必須包含：
1. 網站 Logo 與導覽列。
2. 主視覺區域及網站介紹。
3. 精選主題文章。
4. 文章分類區域。
5. 最新文章列表。
6. 頁尾資訊。

### 文章頁（article.html）
必須包含：
1. 文章標題。
2. 文章分類。
3. 封面圖片。
4. 主題簡介。
5. 文章內容。
6. 韓文單字與例句。
7. 重點整理。
8. 延伸閱讀。

## 4. 文章分類（Categories）

新增文章時，必須選擇以下其中一個分類：

- Hangul：韓文字母與發音
- Daily Korean：日常韓文
- Korean Culture：韓國文化
- Internet Slang：網路流行語
- Language Facts：有趣的語言現象

## 5. 文章內容規範（Content Guidelines）

每篇文章應遵守以下規則：

1. 使用繁體中文作為主要說明語言。
2. 韓文內容必須附上中文翻譯。
3. 韓文單字應附上羅馬拼音或發音提示。
4. 內容以初學者能理解為原則。
5. 避免使用過多專業術語。
6. 透過生活化例子解釋語言現象。
7. 每篇文章至少包含兩個韓文例句。
8. 說明韓文實際使用情境。
9. 涉及語言或文化知識時，應確認內容正確性。

## 6. 文章固定格式（Article Template）

每篇文章必須盡量遵守以下結構：

### A. 主題封面
- 文章標題
- 分類
- 封面圖片
- 一句吸引讀者的介紹

### B. 主題介紹
用簡單的文字介紹這個主題，讓讀者了解為什麼值得認識。

### C. 知識解析
解釋韓文的意思、來源、使用方式或相關文化背景。

### D. 實際使用情境
提供韓文例句，並附上中文翻譯與使用說明。

### E. 重點整理
整理三個值得記住的重點。

### F. 延伸閱讀
推薦其他相關文章。

## 7. 元件使用規範（Components）

所有文章必須優先使用既有共用元件，不可為每篇文章重新設計一套樣式。

建議共用元件：

- Navbar：網站導覽列
- Hero：主視覺區域
- ArticleCard：文章卡片
- CategoryTag：分類標籤
- KoreanWord：韓文單字展示
- ExampleBox：韓文例句區塊
- HighlightBox：重點提示
- Footer：頁尾

若需要新元件，應先確認是否能重複使用，再新增至共用元件中。

## 8. 檔案命名與放置規則（File Structure）

專案使用 HTML、CSS 與 JavaScript 建立靜態網站。

建議檔案結構：

```text
korean-discovery/
├── AGENTS.md
├── index.html
├── article.html
├── css/
│   └── style.css
├── js/
│   ├── articles.js
│   └── main.js
├── images/
│   └── article-images/
└── README.md
```

規則：
- HTML 檔案放在根目錄。
- CSS 樣式集中管理。
- JavaScript 功能集中管理。
- 文章資料統一放在 articles.js。
- 圖片統一放在 images 資料夾。
- 檔案及圖片名稱使用英文小寫與連字號。
- 不可隨意更改既有檔案名稱或資料夾結構。

## 9. AI 修改與新增內容規則（AI Development Rules）

當 AI 接收到新增文章的要求時：

1. 先閱讀本文件。
2. 確認文章分類。
3. 按照既有文章格式建立內容。
4. 優先使用既有元件。
5. 將新文章加入 articles.js。
6. 確保首頁及文章列表能正確顯示新內容。
7. 確認文章頁能正確讀取對應文章。
8. 不得破壞其他已完成的頁面。
9. 不得任意更改網站整體設計。
10. 新增功能後應檢查桌面與手機版面。

當 AI 修改既有功能時：
- 盡量只修改必要的檔案。
- 保留原有功能。
- 不要重複建立相同的元件。
- 修改後檢查是否有錯誤。

## 10. 網站發布規則（Deployment）

- 網站必須支援 GitHub Pages。
- 使用相對路徑載入 CSS、JavaScript 與圖片。
- 不可依賴本機伺服器才能顯示的功能。
- 發布前確認首頁及文章頁都能正常開啟。
- 確認手機與桌面瀏覽沒有明顯排版問題。

## 11. 最重要的開發原則

本專案的核心不是單純製作一個網站，而是建立一套可以持續擴充的內容製作系統。

未來新增任何主題，都必須遵守：

**統一視覺風格、統一文章結構、重複使用共用元件、維持內容品質。**

新增文章應以擴充既有系統為優先，而不是重新製作一個獨立網站。
